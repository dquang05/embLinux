## 1. Shared Memory
- **Essence**: Cooperating processes share a memory region. Fastest IPC as it avoids kernel intervention after setup.
- **Pros**: High performance, zero-copy data exchange.
- **Cons**: Requires manual synchronization (e.g., semaphores/mutexes) by the programmer to avoid race conditions.
- **Details**: [shared_memory.md](shared_memory.md)

## 2. Message Passing
- **Essence**: Processes exchange messages via `send()` and `receive()` primitives. Kernel manages communication.
- **Pros**: Easier to implement distributed systems, no shared memory conflicts.
- **Cons**: Slower due to kernel involvement (system calls) and data copying.
- **Details**: [message_passing.md](message_passing.md)

## 3. Pipes
- **Essence**: A conduit allowing two processes to communicate.
- **Ordinary Pipes**: Unidirectional, requires parent-child relationship. Exists only during communication.
- **Named Pipes (FIFOs)**: Bidirectional, no parent-child relationship needed, persists in the file system.
- **Details**: [pipes.md](pipes.md)

## 4. Client-Server Communication (Sockets & RPC)
- **Sockets**: Low-level endpoint communication (IP + Port). Exchanges unstructured byte streams.
- **RPC (Remote Procedure Call)**: High-level IPC. Abstracts network calls to look like local function calls. Handles parameter marshaling automatically.
- **Details**: [sockets_and_rpc.md](sockets_and_rpc.md)

## 5. IPC Taxonomy & Properties
- **Categories**: IPC is divided into **Communication** (data transfer, shared memory), **Synchronization** (semaphores, locks), and **Signals**.
- **Persistence**:
  - **Process persistence**: Object exists only as long as held open by a process (Pipes, FIFOs, Sockets).
  - **Kernel persistence**: Object exists until explicitly deleted or system reboots (Message Queues, Semaphores, Shared Memory).
  - **File-system persistence**: Object retains information across reboots (Memory-mapped files).
- **Keys and Identifiers (System V IPC)**:
  - Objects are accessed via system-wide identifiers. Keys (`key_t`), usually generated by `ftok()` or `IPC_PRIVATE`, map to these identifiers.
  - To prevent stale connections when a server restarts, the kernel algorithm guarantees that when a new IPC object is created, its identifier will be different from recently deleted objects, even if the same key is reused.

## 6. Synchronization Facilities
- **Semaphores**: Kernel-maintained integer used to manage exclusive access to shared resources (System V and POSIX).
- **File Locks**: Explicitly coordinate operations on the same file (`flock()`, `fcntl()`).
- **Details**: [semaphores.md](semaphores.md)
