# Message Passing

Message passing provides a mechanism for processes to communicate and synchronize actions without sharing the same address space. Useful in distributed environments.

## 1. Core Operations
- `send(message)`
- `receive(message)`

## 2. Design Options
### Naming
- **Direct Communication**: Processes explicitly name each other (`send(P, msg)`, `receive(Q, msg)`).
- **Indirect Communication**: Messages are sent to and received from mailboxes or ports (`send(A, msg)`, `receive(A, msg)`).

### Synchronization
- **Blocking (Synchronous)**: 
  - *Blocking send*: Sender blocks until message is received.
  - *Blocking receive*: Receiver blocks until message is available.
- **Non-blocking (Asynchronous)**:
  - *Non-blocking send*: Sender sends and resumes immediately.
  - *Non-blocking receive*: Receiver retrieves message or null.

### Buffering
- **Zero capacity**: No messages can wait. Sender must block (rendezvous).
- **Bounded capacity**: Finite queue length. Sender blocks if queue is full.
- **Unbounded capacity**: Infinite queue length. Sender never blocks.

## 3. Notable Implementations
- **Mach**: Uses ports (mailboxes) and port rights. Uses virtual-memory management to map sender's message to receiver's address space (avoids data copying).
- **Windows ALPC (Advanced Local Procedure Call)**: Uses connection ports and communication ports. Optimizes message passing using shared section objects for large messages.

## 4. System V Message Queues (Linux/UNIX)
System V message queues are a classic UNIX IPC mechanism with **Kernel Persistence**. They are message-oriented, not byte streams.
- **Key Characteristics**:
  - Each message has an integer type (`mtype`). 
  - Messages can be retrieved by FIFO order, specific type, or as a priority queue.
- **API Overview**:
  - `msgget()`: Creates a new queue or opens an existing one using an IPC key (e.g., generated by `ftok()` or `IPC_PRIVATE`).
  - `msgsnd()`: Writes a message (type + body) to the queue. Can use `IPC_NOWAIT` to avoid blocking if the queue is full.
  - `msgrcv()`: Reads a message. 
    - If `type == 0`: Gets the first message.
    - If `type > 0`: Gets the first message of the exact type.
    - If `type < 0`: Priority queue retrieval (first message of lowest type <= absolute value).
  - `msgctl()`: Control operations like `IPC_RMID` (delete queue instantly), `IPC_STAT` (read info), `IPC_SET` (modify permissions/limits).
- **System Limits** (Viewable in `/proc/sys/kernel/` on Linux):
  - `MSGMNI`: Max number of message queues system-wide.
  - `MSGMAX`: Max size in bytes of a single message.
  - `MSGMNB`: Max total bytes held in a single queue at once.
- **Utilities**: Can be listed with `ipcs -q` (or `/proc/sysvipc/msg`) and removed with `ipcrm -q`.

## 5. Disadvantages of System V Message Queues
- **No File Descriptors**: They use IPC Identifiers instead of standard file descriptors. This prevents them from being easily integrated into I/O multiplexing loops using `select()`, `poll()`, or `epoll()`.
- **Connectionless Nature**: The kernel does not maintain a count of processes referencing the queue (unlike pipes or sockets). It's difficult to determine when a queue can be safely deleted, leading to potential resource leaks or premature data loss.

## 6. POSIX Message Queues
POSIX Message Queues are an alternative to System V Message Queues, providing a simpler and more file-like API.
- **Key Characteristics**:
  - **Reference Counted**: Safe deletion. A queue marked for deletion is only destroyed when all processes close it.
  - **Priority Ordering**: Messages have an associated integer priority. They are always strictly queued and received in priority order (unlike System V's type-based retrieval).
  - **Asynchronous Notification**: A process can request to be notified (via a signal or a new thread) when a message arrives on a previously empty queue using `mq_notify()`.
- **API Overview**:
  - `mq_open()`: Creates or opens a message queue (names must start with `/`). Returns a descriptor `mqd_t`.
  - `mq_send()`: Adds a message to the queue with a given priority.
  - `mq_receive()`: Removes the oldest message with the highest priority.
  - `mq_close()`: Closes the message queue descriptor for the calling process.
  - `mq_unlink()`: Removes the message queue name and marks it for deletion.
  - `mq_getattr()` / `mq_setattr()`: Retrieves or sets queue attributes (like `O_NONBLOCK`).
- **Linux Specifics**:
  - Message queues are mounted as a virtual file system (usually at `/dev/mqueue`).
  - Unlike System V, on Linux POSIX message queue descriptors are actual file descriptors and can be monitored using `select()`, `poll()`, or `epoll`.
